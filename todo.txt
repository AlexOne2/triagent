  - [ ] `.msg` upload/parser not implemented.
- [x] Parse and normalize
  - [x] Headers/hops parsing (including `Received` hop extraction for IP/rDNS in current parser).
  - [~] SPF/DKIM/DMARC signals shown from `Authentication-Results` header parsing only (no independent cryptographic verification engine yet).
  - [x] URL extraction + normalization implemented.
  - [ ] Attachment extraction + hashing pipeline not implemented (attachments table exists, UI currently says "No attachments captured in v0").
- [~] Case lifecycle
  - [x] Case ID available (`reports.id`).
  - [ ] Case fingerprint/dedup workflow not active (legacy clustering removed; fingerprint helper exists but is unused).

- [~] Evidence report export
  - [x] Audit export exists (NDJSON + manifests + chain verification).

- [x] Audit log

## Prioritized next actions
1. Add `.msg` ingestion support and normalize into the existing report schema.
2. Implement attachment extraction pipeline: enumerate MIME parts, hash (`sha256`), store metadata, persist blob to MinIO/filesystem.
3. Add case-level evidence export endpoint/UI (`.md` first, optional PDF render) including artifacts, rationale, and resolution history.
4. Add explicit proposed-verdict workflow (`PROPOSED_*` state + analyst approval transition).
5. Add report retention policy controls (configurable TTL + purge command + audit events for deletions).
6. Add formal security docs: threat model, hardening guide, install/upgrade/rollback runbook.
7. Add SBOM + dependency scan commands in CI/dev (`cyclonedx` + `pip-audit`/`npm audit` report artifacts).
8. Improve observability: structured JSON logs, sensitive-field masking policy, and minimal metrics/alerts.
